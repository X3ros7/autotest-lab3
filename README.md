# Відповіді на контрольні запитання

## 1. Наведіть приклади використання Fake, Stub, Mock

Тестовий дубль (test double) це об'єкт, який замінює реальну залежність у тесті.

- **Stub** повертає заздалегідь задані відповіді і сам нічого не перевіряє. Приклади:
  - `sinon.stub(m, 'exists_wrong_row').returns(true)` змушує `gauss` повернути `null`;
  - `sinon.stub(fs, 'readFileSync')` підставляє вміст `input.txt` без читання диска.
- **Mock** має заздалегідь задані очікування (які методи, з якими аргументами, скільки разів), які перевіряються викликом `verify()`. Приклади:
  - `mock.expects('mull_add').withExactArgs(1, 0, -2).once()` у тесті `gauss_forward`;
  - `mock.expects('writeFileSync').withExactArgs('output.txt', 'no solution').once()` у тесті `write_in_file`;
  - `sinon.mock(Matrix.prototype)` з очікуваннями викликів `set` у тесті `read_input`.
- **Fake** це спрощена робоча реалізація. Приклади:
  - `FakeMatrix`, яка зберігає рядки у масиві в пам'яті, замість класу `matrix`;
  - файлова система в пам'яті на `sinon.fake` замість `fs`.
- **Spy** (додатково) записує виклики, але виконує реальний код: `sinon.spy(m, 'mull_add')` перевіряє, скільки разів і з якими аргументами викликано метод.

## 2. Особливості модульного та приймального тестування

**Модульне:**

- перевіряє окрему функцію, метод або клас ізольовано, залежності замінюють тестовими дублями (stub, mock, fake);
- виконує розробник, метод білої скриньки;
- тести швидкі й автоматизовані, запускаються при кожній зміні;
- швидко локалізує помилку, але не показує, чи відповідає система очікуванням користувача.

**Приймальне:**

- перевіряє систему в цілому на відповідність бізнес-вимогам;
- виконує замовник або користувач, метод чорної скриньки;
- виконується наприкінці розробки в середовищі, схожому на робоче;
- результат: прийняти продукт чи повернути на доопрацювання.

## 3. Призначення бібліотек Sinon та Sinon-Chai

- **Sinon** це бібліотека для створення тестових дублів:
  - шпигуни (`sinon.spy`), стаби (`sinon.stub`), моки (`sinon.mock`), фейки (`sinon.fake`);
  - фальшиві таймери та сервер;
  - `sinon.restore()` повертає оригінальні методи після тесту;
  - не залежить від тестового фреймворка, використовується разом з Mocha та Chai.
- **Sinon-Chai** це плагін для Chai, який додає твердження для дублів Sinon:
  - `expect(spy).to.have.been.calledOnce`, `calledWith(...)`, `callCount(n)`;
  - читабельні повідомлення про помилки замість ручних перевірок `spy.calledWith(...)`;
  - підключається через `chai.use(sinonChai)`.
